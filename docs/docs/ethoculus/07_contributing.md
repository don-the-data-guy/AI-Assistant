# Contributing to Ethoculus

Ethoculus welcomes practical contributions.

The first goal is not theoretical perfection. The first goal is a platform that ordinary people can download, start, understand, and improve.

## Good first contributions

1. Improve install instructions.
2. Test on Windows, macOS, and Linux.
3. Add screenshots.
4. Improve troubleshooting.
5. Test small models.
6. Create beginner-friendly RAG examples.
7. Add ethical review checklists.
8. Add plain-English explanations of AI concepts.

## Contribution rule

If a change makes Ethoculus more powerful but less understandable, explain why the tradeoff is worth it.

## Documentation style

Write like this:

1. Plain language first.
2. Technical depth second.
3. Commands users can copy.
4. Warnings where mistakes matter.
5. Sources where factual claims matter.
6. No fake certainty.

## Ethical review questions

Before opening a pull request, ask:

1. Does this make installation easier?
2. Does this make the system more transparent?
3. Does this protect user control?
4. Does this increase risk for non-technical users?
5. Could this feature be misused?
6. What guardrail or warning should travel with it?

## Pull request checklist

1. Describe the change.
2. Explain why it helps.
3. Include tested operating system.
4. Include commands tested.
5. Include screenshots when UI changes are involved.
6. Update documentation.
7. Add source links for technical claims.

## What not to contribute

1. Hidden telemetry.
2. Unclear model downloads.
3. Undocumented cloud dependencies.
4. Fake benchmark claims.
5. Safety theater.
6. Features that make the user less informed about what the system is doing.

## Community posture

Ethoculus is for builders who want open AI to be usable, inspectable, and accountable.

Be direct. Be kind. Bring receipts.
